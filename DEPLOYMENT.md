"# Deployment

## Overview

This app is prepared for a production deploy on a single VPS with:

- Docker
- Kamal 2
- PostgreSQL 16 as a Kamal accessory
- Rails encrypted credentials and environment variables
- Rails healthcheck at `/up`

## VPS Requirements

- Ubuntu 22.04+ or another modern Linux distribution with Docker support
- Docker Engine installed on the VPS
- SSH access for Kamal
- A DNS record pointing `your-domain.example.com` to your VPS IP
- Open ports `22`, `80`, and `443`
- Sufficient disk for Docker images, PostgreSQL data, and Rails storage volume

## Local Requirements

- Ruby matching [.ruby-version](/home/glopes-a/dev_dashboard/.ruby-version)
- Bundler
- Docker
- Access to the Docker registry you will push to
- Kamal available via the app bundle

Install dependencies locally:

```bash
bundle install
bin/rails db:prepare
bin/rails test
```

## Required Secrets and Environment Variables

These values must be available in your shell before running Kamal:

```bash
export KAMAL_REGISTRY_PASSWORD="replace-me"
export RAILS_MASTER_KEY="replace-me"
export POSTGRES_PASSWORD="replace-me"
export ACTIVE_RECORD_ENCRYPTION_PRIMARY_KEY="replace-me"
export ACTIVE_RECORD_ENCRYPTION_DETERMINISTIC_KEY="replace-me"
export ACTIVE_RECORD_ENCRYPTION_KEY_DERIVATION_SALT="replace-me"
export GITHUB_OAUTH_CLIENT_ID="replace-me"
export GITHUB_OAUTH_CLIENT_SECRET="replace-me"
```

Notes:

- `RAILS_MASTER_KEY` is required if you keep GitHub OAuth secrets in Rails credentials.
- The Active Record Encryption keys are required because `UserGithubCredential#fine_grained_token` uses `encrypts`.
- `SECRET_KEY_BASE` is not required explicitly for this setup because Rails credentials provide it in production.
- `DATABASE_URL`, `CACHE_DATABASE_URL`, `QUEUE_DATABASE_URL`, and `CABLE_DATABASE_URL` are generated by `.kamal/secrets` from `POSTGRES_PASSWORD`.

## Values To Fill In Before Deploy

Update [config/deploy.yml](/home/glopes-a/dev_dashboard/config/deploy.yml):

- Replace `YOUR_VPS_IP`
- Replace `your-domain.example.com`
- Replace `registry.example.com`
- Replace `your-registry-username`
- Replace `your-image-name`

Confirm your GitHub OAuth app callback URL matches:

```text
https://your-domain.example.com/auth/github/callback
```

## PostgreSQL Accessory

The PostgreSQL accessory stores data in a persistent Docker volume and creates:

- `dev_dashboard_production`
- `dev_dashboard_production_cache`
- `dev_dashboard_production_queue`
- `dev_dashboard_production_cable`

Useful commands:

```bash
bin/kamal accessory boot postgres
bin/kamal accessory logs postgres
bin/kamal accessory details postgres
```

## First Deploy

1. Fill in the placeholders in `config/deploy.yml`.
2. Export the required secrets locally.
3. Verify the app locally.
4. Run the initial setup and deploy.

Commands:

```bash
bundle install
bin/rails db:prepare
bin/rails test
bin/kamal setup
bin/kamal deploy
```

## Troubleshooting

`KAMAL_REGISTRY_PASSWORD` missing:

- Export the registry password or access token in your local shell before running Kamal.

`missing encryption key to decrypt attribute`:

- One or more Active Record Encryption variables are missing or do not match the values used when the tokens were encrypted.

OAuth login fails after deploy:

- Verify `APP_BASE_URL` in [config/deploy.yml](/home/glopes-a/dev_dashboard/config/deploy.yml).
- Verify the GitHub OAuth callback URL exactly matches `https://your-domain.example.com/auth/github/callback`.
- Verify `GITHUB_OAUTH_CLIENT_ID` and `GITHUB_OAUTH_CLIENT_SECRET`.

Database connection errors:

- Verify the PostgreSQL accessory is running.
- Verify `POSTGRES_PASSWORD` is exported locally before deploy.
- Verify the generated `DATABASE_URL` values in `.kamal/secrets` still match the accessory hostname and database names.

Healthcheck failures:

- Verify the app boots on port `3000`.
- Verify `/up` returns `200`.
- Verify the Kamal proxy host and SSL settings are correct.

## Security Notes

- Public signup exists. Any GitHub user who can complete OAuth can create a local account.
- GitHub fine-grained tokens are encrypted at rest with Active Record Encryption.
- Sensitive params are filtered from logs via [config/initializers/filter_parameter_logging.rb](/home/glopes-a/dev_dashboard/config/initializers/filter_parameter_logging.rb).
- Rails credentials keys are ignored by git via [.gitignore](/home/glopes-a/dev_dashboard/.gitignore).
- Production now enables `assume_ssl` and `force_ssl`.
- Host authorization is restricted to the configured `APP_BASE_URL` host, with `/up` excluded for healthchecks.
- CSRF protection remains enabled because the app uses `ActionController::Base`.
- Production debug pages remain disabled because `consider_all_requests_local` is `false`.

## Recommended Pre-Launch Checks

- Create a fresh production credentials file and confirm `secret_key_base` exists.
- Confirm the Active Record Encryption keys are backed up securely.
- Confirm the GitHub OAuth app callback URL uses the final production domain.
- Run a real deploy to a staging VPS before first production traffic.
